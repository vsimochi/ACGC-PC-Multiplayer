# Provenance inventories

Evidence files behind [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md). They were generated by read-only scripts against Git (HEAD `16e42a3`) and the public upstream trees (ACreTeam/ac-decomp and flyngmt/ACGC-PC-Port, GitHub API, 2026-10-10). They are inventories, not licence grants.

- `fork-added-files.txt`: the 387 files that exist in this fork but not in the original port, grouped (multiplayer code, headers, tests/tools, relocated data wrappers, docs).
- `modified-files-outside-target-pc.txt`: files in `src/`/`include/` touched by non-FlyingMeta authors whose content has no `TARGET_PC` block, in groups A (third-party commits already in the original port), B (fork edits), C (mechanical relocation), D (new fork support), E (mixed).
- `sdk-header-inventory.txt`: which identifiers of the SGI/Nintendo-marked headers `include/PR/*.h` are referenced by the rest of the tree.

## SDK-marked headers: what a replacement would involve (assessment only, nothing was replaced)

- All five headers are included by about 3400 of the 4041 compiled translation units (`PR/gbi.h` pulls in `abi.h`, `mbi.h`, `ultratypes.h`). 388 of 1093 identifiers are used elsewhere (gbi.h 350/936, abi.h 23/50, gs2dex.h 6/85, mbi.h 6/16, ultratypes.h 4/6).
- The use is dominated by display-list command macros (`gsSPVertex`, `gsSPTexture`, `gsDPSetCombineLERP`, ...) and `G_*` constants in the 3221 `src/data` objects and in the GBI interpreter.
- Technically a smaller, independently written header is possible and checkable: build `src/data` with both header sets and compare the generated bytes. It is a multi-week task, must not be derived by copying the existing text, and its clean-room status would need documentation. The `gs2dex.h` part alone is small (6 identifiers used).
- Replacing the headers would NOT resolve the status of the reconstructed libraries and data tables (JSystem, jaudio_NES, Famicom, libforest/emu64, libc64/libu64, `src/data`), which stay a separate question.
